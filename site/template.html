Forecasting freeway traffic flow 15 minutes ahead

Seven forecasting models were trained on real PeMSD4 loop-detector data under one identical setup and scored on the same unseen final nine days (20–28 Feb 2018). Each one predicts the flow 15 minutes ahead from the last 60 minutes. Six models read one sensor's history. STGCN reads all 307 sensors at once, together with the road network that connects them.

    How the experiment works

    Pipeline

    1. Validate the raw file: 16,992 steps × 307 sensors, no NaN or negative values.
    2. Treat zero flow as a sensor failure. Fill gaps of up to 1 hour in time and drop longer gaps.
    3. Split the timeline 70 / 15 / 15 in order (train, validation, test). Nothing is shuffled.
    4. Build windows of 12 readings (60 min) → the target 3 steps later (15 min).
    5. Pick each model's settings with a small grid search on the validation set.
    6. Freeze and save every model, then score the test set once.

    Leakage rules (checked by the audit script)

    • The scaler is fitted on training readings only.
    • The reading at forecast time t must be real, so gap-filling never uses readings after t.
    • Targets are real readings. Interpolated values are never scored.
    • Windows never cross a split boundary.
    • Tuning and early stopping use validation data only.
    • STGCN uses a neighbour's reading only if it was known by time t. Anything else is zeroed and flagged. It is scored on exactly the same test samples.

    The spatial model (STGCN)

    STGCN (Yu et al., 2018) combines graph convolutions over the road network with gated convolutions over time. Its graph comes from distance.csv, published with PeMSD4: 340 road links between the 307 sensors, weighted by distance. Settings were chosen on the validation set.

    The hybrid model

    The LSTM does not vote. After training, it is frozen, and its hidden state becomes extra input for XGBoost.

    Findings

    These findings were generated from the result files and apply to this dataset, horizon and setup.

      Limitations

      • One dataset (Bay Area, 59 days) and one horizon (15 min).
      • Only flow history, calendar time and (for STGCN) the road graph are used. There is no weather or incident information.
      • There is one training run per model, so the 0.4% (hybrid vs XGBoost) and 2–3% (STGCN vs hybrid) gaps have no confidence intervals.
      • The sensor graph's geography cannot be checked directly, because there are no coordinates. Connected sensors do show more strongly correlated traffic.
      • Times when the sensor was offline at the forecast moment are not scored.

      Run it yourself

      Code, data and trained models: github.com/ANSHSINGH5999/traffic-flow-forecasting. The Streamlit demo loads the saved models, so nothing is retrained.

      git clone https://github.com/ANSHSINGH5999/traffic-flow-forecasting.git && cd traffic-flow-forecasting
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt                    # macOS also needs: brew install libomp
python -m pytest -q tests                          # 26 tests
python scripts/audit_experiment.py                 # data, leakage, models, app
python -m experiments.stgcn.run_stgcn --mode final  # STGCN (7th model)
streamlit run app/app.py                           # open http://localhost:8501
